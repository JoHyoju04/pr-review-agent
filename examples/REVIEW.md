# REVIEW.md

## 우선순위
1. 실제 버그 (데이터 손실, 크래시, 잘못된 결과)
2. 보안 문제
3. 그 외는 지적하지 않는다

## 영역별 "실패"의 정의
- `<경로>`: <이 영역에서 실패란 무엇인가>
- `docs/`: 코드와 다른 말을 한다
- `config/`: 엉뚱한 환경으로 라우팅된다

## 건너뛸 경로
- `generated/`, `vendor/`, `*.lock`, `**/__snapshots__/`

## 코멘트 규칙
- 모든 지적에 `파일:라인`과 근거 코드를 붙인다. 이름만 보고 추측하지 않는다.
- Nit은 PR당 최대 3개.
- 포맷팅, 네이밍 취향, import 순서는 린터 몫이므로 언급하지 않는다.
- 이 PR이 만들지 않은 기존 문제는 `pre_existing`으로 표시한다.

## 요약 형식
- 첫 줄은 개수로 시작한다. 예: "Important 1, Nit 2"
- 지적할 게 없으면 "수정할 사항 없음"이라고만 쓴다.
